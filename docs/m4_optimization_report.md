# M4 ItemCF 性能优化与 Bad Case 报告

## 改动

- 使用稀疏用户—商品矩阵离线计算物品余弦相似度。
- 每件商品只保留 Top-100 相似邻居。
- 评测期间复用同一个 ItemCF 索引，避免每个请求重建共现关系。
- 评测从 50 名用户扩大至 200 名用户。
- 保存逐用户目标商品、推荐列表、命中排名、延迟和 Bad Case 类型。

## 200 用户实验

| 模型 | HitRate@10 | NDCG@10 | 覆盖率 | P95 延迟 |
|---|---:|---:|---:|---:|
| Popular | 2.5% | 0.0182 | 1.25% | 14.49 ms |
| ItemCF | 1.0% | 0.0032 | 10.88% | **7.25 ms** |
| Text Vector | **7.5%** | 0.0263 | **76.50%** | 22.42 ms |
| Hybrid | 4.5% | **0.0287** | 53.50% | 44.37 ms |

## 性能变化

- ItemCF P95：147.98ms → 7.25ms，降低约 95%。
- Hybrid P95：185.17ms → 44.37ms，降低约 76%。

## Bad Case 结论

- 200 个测试用户中，混合召回命中 9 个，191 个目标商品未进入 Top-10。
- 文本向量的 HitRate 高于当前等权 RRF 混合结果，说明热门和 ItemCF 信号可能稀释文本信号。
- 下一步应学习或搜索融合权重，并把未命中进一步拆分为“候选未召回”和“已召回但排序靠后”。
