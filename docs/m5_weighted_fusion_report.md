# M5 加权融合与 Bad Case 分层报告

## 实验设计

- 前 100 名测试用户作为权重验证集。
- 后 200 名用户作为独立测试集，不参与权重选择。
- 比较等权、文本 ×2、文本 ×3、文本与 BM25 同时加权四种方案。
- 权重选择首先比较 HitRate@10，命中率相同时比较 NDCG@10。

## 权重选择

验证集最优配置：

```json
{
  "popular": 1.0,
  "item_cf": 1.0,
  "bm25": 1.0,
  "text_vector": 2.0
}
```

该配置在独立测试集上的结果：

| 指标 | 结果 |
|---|---:|
| HitRate@10 | 9.5% |
| NDCG@10 | 0.0385 |
| 商品覆盖率 | 63.13% |
| P95 延迟 | 47.99 ms |
| Candidate Recall@50 | 20.0% |

相较 M4 等权融合的 HitRate@10 4.5%，本阶段结果增加 5 个百分点。由于两次实验的测试用户切片不同，不把它表述为严格的相对提升比例；后续应在同一固定测试集上补充正式对照。

## Bad Case 分层

| 类型 | 数量 | 含义 |
|---|---:|---|
| Hit | 19 | 目标商品进入 Top-10 |
| Ranking miss | 21 | 目标进入 Top-50 候选池，但未进入 Top-10 |
| Candidate not recalled | 160 | 目标未进入 Top-50 候选池 |

当前 88.4% 的失败来自候选未召回，因此下一阶段的优先级是增加召回来源和改善用户兴趣表示，而不是继续单独调排序参数。
